Stubwise can build a **knowledge graph of each connected repository** using
[graphify](https://github.com/Graphify-Labs/graphify): every class, function and
file becomes a node, and their relationships (`calls`, `imports`, `inherits`, …)
become edges, each tagged with its provenance and exact `file:line` location.

The extraction is **AST-based and fully local** (tree-sitter): building the
graph costs **zero LLM tokens**. The only optional AI step is naming the
detected communities, done with a single Claude CLI call.

It complements the [autogenerated documentation](/guide/documentation/autogenerated/):
the docs explain the *why and how* in prose, the graph answers *structural*
questions — "what calls this?", "how are these two modules connected?" —
instantly and deterministically.

## Enabling it

1. Open the repository detail page (**Repositories → your repo**) and turn on
   the **Code graph** toggle (admin only, off by default).
2. Go to the **Docs** section → your repository → **Graph** tab and click
   **Generate graph**. The first build takes about a minute on a large monorepo.

From then on the graph **updates itself on every push** to the default branch
(debounced), incrementally — unchanged files are cached.

## What you get

- An **interactive graph** (zoom, click nodes, filter; expandable to full page).
- A **report** with the most connected symbols ("god nodes"), the detected
  communities with AI-generated names, and surprising cross-module connections.
- The raw **`graph.json`** to download and query from the terminal.
- **Rebuild from scratch** (admin) re-extracts everything ignoring the
  incremental cache — the escape hatch if the graph ever looks stale.

> The interactive view loads the vis-network library from a CDN: on a machine
> without internet access the report and metadata still work, only the
> interactive rendering is unavailable.

## The setup PR

From the Graph tab an admin can open a **setup PR** on the repository itself.
It commits the current graph plus the configuration developers need:

- `graphify-out/` — the graph, the report and the incremental manifest;
- `.mcp.json` — a `graphify` MCP server entry (started via `uvx`, no install
  needed if [uv](https://docs.astral.sh/uv/) is present);
- `CLAUDE.md` — a query-first section telling AI assistants to prefer
  `graphify query` over grepping;
- a project-scoped `/graphify` skill, ignore rules and a merge driver for
  `graph.json`.

After merging, each developer runs **once**:

```sh
uv tool install graphifyy
graphify hook install
```

`graphify hook install` registers the post-commit hook (local incremental
rebuild of the graph) and activates the `graphify-union` merge driver — the
`.gitattributes` line alone does not.

### Requirements

| Requirement | Needed for |
|---|---|
| [uv](https://docs.astral.sh/uv/) (or Python 3.10+ with pipx) | running the MCP server via `uvx`, installing the CLI |
| `uv tool install graphifyy` | terminal queries, the post-commit hook, the merge driver |
| Claude Code (or any MCP client) | querying the graph from an AI session |

## Using it from Claude Code

**Started from the repository root**, everything is automatic: Claude Code picks
up the committed `.mcp.json` (approve the `graphify` server on first use) and
the project skill, and gets the `query_graph`, `get_node`, `get_neighbors` and
`shortest_path` tools.

**Started from a parent folder** (a workspace containing several repositories —
common for cross-repo work) the committed `.mcp.json` is **not** loaded: Claude
Code only reads it from the directory it was started in. Register the server at
the **user level** instead — once per machine, works from any folder:

```sh
claude mcp add -s user graphify -- uvx --from "graphifyy[mcp]==0.9.28" python -m graphify.serve
uvx --from "graphifyy[mcp]==0.9.28" python -c "import graphify"
graphify install
```

The three lines: register the server, **pre-warm** the `uvx` cache, and
(optionally) install the user-level `/graphify` skill. No inline comments in
the block on purpose: default `zsh` passes `# …` to the command as arguments
when pasted interactively.

The **pre-warm line matters**: the very first `uvx` run downloads and builds the
server's environment (it can take minutes), while Claude Code gives an MCP
server ~30 seconds to start — so without pre-warming, the first session shows
the server as **failed**. Run the pre-warm once (or just pick *Reconnect* in
`/mcp` after the environment finishes building); every later start takes about
a second, straight from the cache.

Started outside a repository the server runs in **multi-project mode**: every
tool accepts a `project_path` argument — the absolute path of the repository
(the folder containing `graphify-out/`) you want to query. Claude passes it
automatically when you tell it which repo you are working on.

From the terminal, the equivalent cross-repo form is:

```sh
graphify query "where is authentication handled?" --graph path/to/repo/graphify-out/graph.json
```

## Troubleshooting

- **The MCP server does not appear in a session** — check where you started
  Claude Code from: project `.mcp.json` files only load from the startup
  directory (see the user-level registration above), and new project servers
  must be approved once.
- **`/mcp` shows the server as failed** — almost always the first-run cold
  start: `uvx` is still building the environment and Claude Code's ~30s startup
  timeout fires first. Run the pre-warm command above (or wait a minute), then
  *Reconnect*.
- **`graphify hook install` targets the wrong repository** — the hook installs
  into the repository of the *current directory*: run it from the root of the
  repo whose graph you want rebuilt on commit (`graphify hook uninstall`
  removes a misplaced one).
- **The graph looks out of date** — pushes to non-default branches do not
  trigger rebuilds; use **Regenerate** in the Graph tab, or check that the
  repository webhook is delivering push events.
- **A build failed** — the Graph tab shows the reason; the previous graph stays
  intact and queryable. **Rebuild from scratch** clears any incremental-cache
  issue.
