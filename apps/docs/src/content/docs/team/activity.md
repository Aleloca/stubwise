Stubwise can write your team's **daily standup for you**. Every night the
worker reads the previous day's commits across a project's repositories and
produces a report in the **Activity** section: an **AI-written description for
every commit** (from the actual diff, not just the message), a **project
summary** on top, and a cross-project **per-developer rollup**.

## Enabling it

The report is **off by default**. On the **project page**, an admin turns on
the **Daily activity report** toggle: from then on, the worker generates a
report for each day with activity (the first one appears after the next UTC
midnight, covering the previous day).

:::note[Link git identities first]
Commits are attributed by their **author email**. To resolve authors into team
members, link each member's git emails from the [team page](/docs/getting-started/web-app/#git-bitbucket--slack-identities)
(**Link git**, multiple emails per member; Bitbucket username separately).
Unresolved authors still appear in the report — flagged as *"Git identity not
linked to a member"* — and can be linked inline from the report itself with
**Link team member**.
:::

## What gets generated

- **One description per commit.** The agent reads each non-merge commit's diff
  and writes an adaptive technical description: one sentence for a small
  change, a paragraph for a large one. All the day's commits are described —
  there is no cap.
- **A project summary.** Once the commits are described, a synthesis step
  writes a short narrative of the project's day.
- **A per-developer rollup.** When *all* the day's enabled projects are done,
  a cross-project summary is written for each developer. Until then the UI
  shows *"Summary in progress…"*.

Commits are attributed to the day of their **committer date**, in UTC.

## The Activity views

The **Activity** section (top navigation) shows one day at a time, with a date
picker and two tabs:

- **By project** — each project's summary followed by its commits, grouped and
  collapsible;
- **By developer** — each person's cross-project summary and commits.

Headers show the raw numbers (commits, authors, projects); each commit expands
into its AI description, rendered as markdown.

## Generating and regenerating

- **Manual generation.** On a date without a report, admins get **Generate
  report for this day**: the report is queued and generated by the worker
  within a few minutes.
- **New commits after generation.** If commits are pushed to a day that was
  already generated (e.g. pushed late), the push webhook triggers a git-only
  recount and the report shows a **"N new commits"** badge with the warning
  *"new commits not included since the last generation"*. An admin can press
  **Regenerate** to rebuild it.
- **Regeneration is incremental.** Descriptions of commits already described
  are **reused** (a description depends only on the immutable diff); only new
  commits get fresh agent runs. The project summary and the developer rollups
  are always rewritten. Regenerating clears the badge.

:::caution[Cost]
A report is **one agent run per commit**, serialized with the project's other
AI jobs. On busy projects this is dozens of short runs per day — that's the
price of descriptions grounded in the diffs. `DAILY_REPORT_MAX_AUTHORS_PER_PROJECT`
bounds the AI summaries on very large teams.
:::

## Configuration

Worker environment variables (see the
[configuration reference](/docs/reference/configuration/)):

| Variable                               | Default | Notes                                                                  |
| -------------------------------------- | ------- | ---------------------------------------------------------------------- |
| `DAILY_REPORT_POLL_MINUTES`            | `15`    | Poll interval of the report poller in minutes. `0` disables it.        |
| `DAILY_REPORT_MAX_AUTHORS_PER_PROJECT` | `25`    | Max authors per project for the AI summaries (beyond: raw data only).  |
| `DAILY_REPORT_RETENTION_DAYS`          | `90`    | Days of retention before old reports are cleaned up.                   |
