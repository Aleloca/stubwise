If you work with a team that uses Stubwise but you are not a developer, you
can still use [Claude Code](https://claude.com/claude-code) to talk to it. You
describe what you need in plain language; Claude reads the project's
documentation, files your request, and the maintainers are notified.

## What you need

- **Claude Code** installed and signed in on your computer.
- **Node.js** (the installer uses `npx`).
- A **Stubwise account** on your team's instance.

## Installing

1. Open Stubwise on the web and go to **Settings → Claude Code**.
2. Click the button to create an access token. The page shows **one command**
   — copy it and paste it into a terminal. The token is displayed only once.
3. The command saves the connection in a small file in your home folder
   (`~/.config/stubwise/config.json`, readable only by you) and installs the
   Stubwise plugin. It checks the token before saving it, so a typo is
   reported right away.
4. Restart Claude Code.

You do not need to clone any repository or link a folder to a project.

## What you can ask

Just write naturally. For example:

- "How does the checkout flow work in the shop project?"
- "Something is broken: the invoice PDF is empty when I download it."
- "It would be great if customers could export their orders."
- "What happened to the requests I sent last week?"

Claude can search the project's [documentation](/guide/documentation/autogenerated/)
and read a page in full, so answers come from what the team has actually
documented. If the documentation does not cover your question, Claude says so
instead of guessing.

## Reporting a bug or asking for a feature

When you describe a problem or a wish, Claude asks which project it belongs
to if that is not clear, then files it for you. Depending on how the project
is set up, it becomes a **ticket** or an entry in the project's **backlog**.
If a similar request is already there, yours is **merged** into it and Claude
tells you, so nothing is duplicated and every requester is remembered.

As soon as you file a bug or request, the project's **maintainers receive a
notification** (in their inbox and as a push notification on the mobile app).
You do not need to message anyone separately.

## Following your requests

Ask "what are my requests?" at any time. Claude lists the bugs and requests
you filed, with a status in plain words, such as *received*, *being looked
at*, *being worked on*, *waiting for review* or *done*. You see only your own
requests.

## Good to know

- Claude Code cannot approve plans, merge changes or deploy anything: that
  stays with the maintainers.
- If you revoke the token (Settings → Access tokens), Claude Code stops
  working until you run a new install command.
- Developers who work inside a repository should also read
  [Claude Code (MCP)](/guide/integrations/claude-code-mcp/).
