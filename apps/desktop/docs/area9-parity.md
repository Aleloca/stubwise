# Area 9a e 9b — parità con il web (30 ott 2026)

Una riga per ogni voce delle sezioni A (Personale → Preferenze) e B (Persone e
accessi) di `area9-inventory.md`, fatte in 9a; poi C (Istanza) ed E (Server e
repository d'istanza), fatte in 9b; poi le voci **fuori** col motivo e le voci
D rimandate al 9c. Percorsi relativi a `src/renderer/`. Stessa regola delle
aree precedenti: il test citato (titolo fra virgolette, anche solo l'inizio)
esercita davvero quella voce; dove non c'è, la colonna lo dice.

In sintesi: l'ingresso è `pages/entry/` (login, invito, reset, primo avvio);
le Preferenze sono `#/preferences/<sezione>`; Amministrazione è `#/admin/*`;
Members è Progetto → Settings → Members (`#/p/<CODE>/settings/members`).
«REAUTH» = la voce chiede la riconferma (`layout/ReauthDialog.tsx`,
`data/auth/reauth.ts`). Le voci del 9b vivono in `pages/admin/ai/`,
`pages/admin/integrations/` e `pages/admin/instance/`, coi dati in
`data/instance/` (e `data/servers/` per i server); le scelte del controller
che le fanno divergere dal web sono scritte nella riga e, per esteso, in
`ossatura-follow-ups.md` («Area 9b — minori aperti»).
