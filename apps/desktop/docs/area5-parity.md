# Area 5 — parità con il web (25 ott 2026)

Una riga per voce della sezione «Documentation» dell'inventario
(`web-inventory.md`, ~406–465), poi le voci **nuove** del Drive, che sul web
non esiste e quindi non hanno parità. Percorsi relativi a `src/renderer/`.
Stessa regola delle aree 2–4: ogni test citato esercita davvero quella voce
(nome del test fra virgolette); «area N» = voce assegnata altrove; ciò che non
c'è sta in «Buchi». In sintesi: l'hub `/docs` del web diventa la sezione
**Docs** del progetto (`#/p/<PRJ>/docs`), lo spazio di un repository è
`#/p/<PRJ>/docs/<repo>`, la pagina `…/<slug>`.

## Buchi

Non costruiti (nessuno è una voce che il prototipo promette):

1. **Filtro per fonte del registro decisioni**: il web ha il filtro, il
   registro dell'Overview (area 2) mostra la fonte ma non filtra.
2. **Pagina `/docs` trasversale ai progetti**: sostituita dalla sezione Docs
   di ogni progetto (scelta di navigazione, come per Settings in area 2).
3. **Il commit della pagina non è un link** (non c'è un target «commit» nel
   prototipo) e le pagine manuali non mostrano l'autore (il modello non ce l'ha,
   il web neanche).

## Riassegnate

Nessuna: tutto ciò che l'inventario mette sotto «Documentation» è o costruito
o in «Buchi».
